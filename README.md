# devintest

Single-page application foundation built with React, TypeScript, Vite, and TanStack Router.
Oxlint handles linting and Oxfmt handles formatting.

## Requirements

- Node.js 24 (see `.nvmrc`)
- npm (repository uses `package-lock.json`)

## Setup

```bash
nvm use          # optional, matches .nvmrc
npm install
npx playwright install --with-deps chromium   # only needed for end-to-end tests
```

## Development

```bash
npm run dev      # Vite dev server on http://localhost:5173
```

## Verification commands

| Command                | Purpose                                                          |
| ---------------------- | ---------------------------------------------------------------- |
| `npm run typecheck`    | Strict TypeScript project build check (`tsc -b`)                 |
| `npm run lint`         | Oxlint over the whole repository (`npm run lint:fix` to autofix) |
| `npm run format`       | Oxfmt, writing files in place                                    |
| `npm run format:check` | Oxfmt in check mode; fails when files are unformatted            |
| `npm test`             | Vitest + React Testing Library component tests                   |
| `npm run test:e2e`     | Playwright smoke tests (builds and serves the app automatically) |
| `npm run build`        | Type check plus production bundle into `dist/`                   |
| `npm run preview`      | Serve the production build locally                               |

## Folder structure

```
e2e/                     Playwright end-to-end specs
src/
  app/                   App shell, global styles, router test
  features/              One folder per feature; add new features here
    about/               Second page, used to verify navigation
    home/                Placeholder home page and its component test
  routes/                TanStack Router file-based routes
    __root.tsx           Root layout (renders AppShell) and not-found component
    index.tsx            `/`
    about.tsx            `/about`
  routeTree.gen.ts       Generated by the router plugin - do not edit
  shared/                Cross-feature components, hooks, and utilities
  test/                  Vitest setup
```

Each feature owns its components, tests, and feature-local logic. Component tests live
next to the component they cover (`HomePage.tsx` / `HomePage.test.tsx`).

## Routing

Routing uses TanStack Router's file-based routing via `@tanstack/router-plugin/vite`, which
must run before `@vitejs/plugin-react` in `vite.config.ts`.

- A file in `src/routes/` becomes a route: `index.tsx` -> `/`, `about.tsx` -> `/about`.
  Each exports `Route = createFileRoute('<path>')({ component })`.
- `src/routes/__root.tsx` is the layout shared by every route; it renders `AppShell` around
  an `<Outlet />` and supplies the not-found component.
- Route components stay thin: they import the page component from its feature folder.
- `src/routeTree.gen.ts` is generated on `npm run dev` / `npm run build` (and committed).
  Never edit it by hand; it is excluded from Oxlint and Oxfmt.
- The router instance and its type registration live in `src/main.tsx`.

### SPA fallback in production

All routes are served from a single `index.html`. `vite dev` and `vite preview` handle this
automatically, so deep links such as `/about` work locally. Any production host must be
configured to rewrite unknown paths to `/index.html` (e.g. an S3/CloudFront error-document
rule, Nginx `try_files $uri /index.html`, or a Netlify/Vercel rewrite); otherwise a refresh
on `/about` returns a 404. No host is configured in this repository.

## Accessibility

The shell uses semantic landmarks (`header`, `nav`, `main`, `footer`), a visible-on-focus
skip link that moves focus to `main`, and a global `:focus-visible` outline. The home page
content is reachable and operable with the keyboard alone.

## Intentionally not included yet

These were left out to keep the foundation minimal. Suggested landing spots when needed:

- **State management** (e.g. Zustand, Redux Toolkit): start with React state inside a
  feature; promote to a store under `src/app/` (providers) or `src/shared/` only when
  state is genuinely cross-feature.
- **UI framework / design system**: replace `src/app/styles.css` and introduce shared
  primitives under `src/shared/`.
- **API client / data fetching** (e.g. TanStack Query, generated client): add a
  `src/shared/api/` module for transport and per-feature hooks for queries.
- **Authentication**: add a provider in `src/app/` and use route `beforeLoad` guards.
- **Mock services** (e.g. MSW): add handlers under `src/test/` and wire them into the
  Vitest setup file and the Playwright web server.
